**Date:** 2026-08-30 · **Scope:** `Dashboard/index.html` (3,109 lines) + the data it renders

## 1. The one-sentence diagnosis

The dataset is a *ledger* — phase notes are changelog paragraphs written for archaeology.
The UI treats every ledger field as **display copy** and prints it raw. So the landing page
answers *"tell me everything ever known about this portfolio"* when a daily check-in needs
*"what changed, what's on fire, what's waiting on me."*

Both questions are answerable from the data that already exists. Only the first one is being asked.

## 3. What a daily check-in actually needs

The check-in loop, in order:

1. **Did anything break?** → blockers, urgent audit findings, stale data
2. **What moved since I last looked?** → dated activity feed, marked *new since your last visit*
3. **What's waiting on me?** → owner-gated decisions, reminders
4. **What do I do next?** → ranked next-actions

Everything else — phase archaeology, codebase graph, toolkit, per-phase task lists — is **reference**.
Reference must remain reachable. It must not be the landing page.

## 4. The rework

### 4.1 New default view: **Today**

Four bands, one screen:

- **Attention** — blockers, urgent audit findings, stale-data warning. Each row is actionable and links straight to its project.
- **Since your last check-in** — the 56 dated `recent` entries merged across all 12 projects into one reverse-chronological feed, grouped by day, with entries newer than the last visit (`localStorage: dash.lastVisit`) flagged. Falls back to "last 7 days" on first run.
- **On your desk** — `pendingDecisions` + `blockers` + `reminders`, grouped by project, deduplicated. This is the owner-gated queue.
- **Movement** — projects that actually moved in 14 days, with sparkline + last-commit line. Dormant projects collapse into a single "Quiet" row.

### 4.2 Kill the prose wall

- Phase notes clamp to **2 lines**, expand on click (full note preserved, nothing lost).
- Derive a **status chip** from the note's leading token (`ACTIVE` / `CLOSED` / `PARTIAL` / `LIVE` / `ON HOLD` / `CONDITIONAL` / `PROPOSAL` / `PLACEHOLDER`) — parses cleanly for the phases that use the convention, falls back to no chip.
- Projected effect: Overview **9,003 → ~1,900 px**; BIMpossible **16,176 → ~3,400 px**.

### 4.3 Navigation

- Group into **Today / Work / Reference / Personal**; dormant projects collapse under a disclosure.
- Nav rows become real `<button>`s inside a `<nav>` landmark: focusable, `aria-current`, 44 px min height.
- **Command palette** (`Ctrl/Cmd-K`) searching projects, views, phases, and activity entries.
- `g` then a key for direct jumps; `?` for the shortcut sheet.

### 4.4 Accessibility pass

- `--dim` → `#707d97` (4.83:1), `--status-dim` → `#7884a0` (5.34:1).
- All interactive elements ≥ 44 px, visible focus ring.
- Skip link, `<nav>` landmark, `aria-current="page"`, real `<h3>` section headings.
- Replace emoji icons with the existing inline-SVG `ICO` set.

### 6.4 Root causes worth remembering

- **Contrast must be measured on the composited surface.** Reading
  `getComputedStyle().backgroundColor` returns the *specified* rgba, not the painted colour, and
  produced 974 false failures. The binding surface here is the lightest raised card,
  `rgb(27,34,56)` — not `--bg #07080d`, which flatters every value by roughly 1.2.
- **A bare `fr` grid track is `minmax(auto, 1fr)`,** and the auto minimum is the item's
  min-content. One phase card with a 557 px min-content stretched its track past a 360 px
  viewport. Every text-bearing track is now `minmax(0, 1fr)`.
- **Inline styles beat responsive CSS.** The DAG chips carried `white-space:nowrap` inline, so no
  media query could let them wrap. Their presentation now lives in a class.
- **`overflow-wrap` is inherited,** so one `break-word` on `#main` covers every ledger string in
  every view; the flex and grid items that also need a smaller min-content get `anywhere`
  explicitly.
- **The UA sheet's `[hidden]{display:none}` is a bare attribute selector,** so any class that sets
  its own display outranks it. `.tk-grid{display:grid}` meant seven "collapsed" Toolkit sections
  kept their full height while correctly reporting `hidden === true`. A global
  `[hidden]{display:none!important}` now has the last word, since every disclosure here relies on
  the property.
- **Never override `display` in a blanket sizing rule.** `#main button{display:inline-flex}` — added
  to make min-height bind on inline chips — silently clobbered `.tv-row`'s `display:grid` and
  staggered the Movement band. Sizing rules set sizes; only the named inline chips get a display.

### 6.5 Left standing

These are known and deliberately not fixed here. The first two are data-layer problems; the third
was introduced upstream after this rework branched and is flagged for the owner.

- **BIM Watch** still renders ~3 words in a 900 px view. It is a data problem, not a UI one — the
  view is wired and will fill when the feed does.
- **Emoji in `data.js`** are ledger content regenerated by the sync scripts; normalising them
  belongs upstream in the generator, not in the renderer.
- **`data.js` on `main` has lost its phase-completion-model fields.** As of commit `c16a1ee`
  ("dashboard refresh 2026-08-31 06:00", written by the automated daily job), `data.js` contains
  **zero** `id:`, `bucket:`, or `weight:` keys on any phase. That is the schema Phase Completion
  Model v1 depends on, so on a clean `origin/main` checkout `validate_dashboard.py` reports 60
  errors, `test_renderer.js` and `test_phase_metrics.js` each fail their active-phase count
  assertion (14 vs 13), and one `test_phase_completion_model.py` case fails its fixture setup. The
  UX branch changes only `index.html` and reproduces these failures exactly, unchanged. This is a
  sync/generator defect in another lane — the daily regeneration is overwriting curated model
  fields — and fixing it is explicitly outside this rework's scope.

### 6.7 Disclosure closeout — as built

Both disclosure surfaces now follow one contract, implemented once in `index.html`
(`DISCLOSURE_KEY`, `readSecOpen`, `writeSecOpen`, `secInitialOpen`, `secToggle`).

**Initial open state, in strict precedence:**

1. A **valid stored preference** for that exact section wins — in both directions. An explicitly
   closed section stays closed even when it is the only one on screen.
2. Otherwise, if the current filter leaves **exactly one section rendered**, that section opens —
   otherwise the filter's own result would be invisible. For Strategy this counts what survives the
   *lane* filter too, not just an explicit category tab. This is a render-time convenience and is
   **not written to storage**, so clearing the filter cannot silently overwrite a real choice.
3. Otherwise **closed**.

Nothing opens for being first. A fresh visit to either view shows every section folded.

**Storage.**

| View | Key | Value |
|---|---|---|
| Strategy | `strat.secOpen` | `{"<categoryId>": true \| false}` |
| Toolkit | `dashboard.v2.toolkit.secOpen` | `{"<sectionCat>": true \| false}` |

Strategy keeps its original key so preferences made before this change survive; Toolkit is new and
takes the namespaced, versioned name, so a future schema change bumps `v2` rather than silently
misreading old values. Section identities are stable ids (`blindspot`, `idea`, …; `agent`,
`command`, `connector`, …), never display labels.

**Failure behaviour.** Every read is defensive and every failure resolves to *closed*, never to a
thrown error or a blank view: a missing key, a disabled or private-mode store that throws on access,
unparseable JSON, a non-object (array / string / number / null), and non-boolean or stale entries
inside an otherwise valid map — a half-valid map keeps only its boolean entries rather than being
partially trusted. A write that cannot land (quota exceeded, storage blocked) leaves the fold
working for the current session and simply unremembered; it never breaks the toggle.

**This state is local to one browser.** It lives in `localStorage`, is never sent anywhere, is not
part of the dashboard's shared data, and does not sync between machines, browsers, or profiles —
clearing site data resets both views to all-collapsed, which is the intended default anyway.

**Accessibility.** `aria-expanded` on the button, the caret rotation (driven off `aria-expanded`),
and the `hidden` property on the `aria-controls` target are always set together; the browser sweep
below asserts they never disagree in any state. Filtering can never strand a matching card inside a
folded section.

### 6.10 Project detail view — third pass, 2026-08-31

The first two passes fixed the *list* surfaces and left the project page nearly untouched. Opening
BIMpossible Platform still gave you a wall of bold ledger prose above the one line that says what to
do, then 18 phase rows stacked flat, with finished work rendered at exactly the same visual weight as
live work.

**Hero reading order.** The card now reads *call to action → when it last moved → full status*:

1. `If you only do one thing` — the focus line, first.
2. Last activity date, age and summary; branch.
3. The status note, in body type, clamped to three lines with a **Full status** disclosure.

The status note keeps every word — BIMpossible's runs ~1,300 characters of `#`-numbered ledger
detail — it just no longer charges admission for the rest of the card. With no focus line the status
note *is* the summary, so it renders unclamped.

**Phase grouping.** Phases are grouped by the same status chip already printed on the row, so the
grouping is literally what is on screen:

| Group | Chips | Default |
|---|---|---|
| In motion | `LIVE`, `ACTIVE`, `PARTIAL`, and any phase with no chip | **open** |
| Parked · conditional | `ON HOLD`, `CONDITIONAL`, `PROPOSAL`, `PLACEHOLDER` | closed |
| Done | `CLOSED` | closed |

An unchipped phase has no declared status, so it reads as live work rather than being folded away on
a guess. A project whose phases all land in one group renders the plain flat list — a lone header
over everything would only add a control that can hide the whole card.

Group state uses the same contract as Strategy and Toolkit, under `dashboard.v2.project.phaseGroups`,
keyed on the stable group id (`motion` / `parked` / `done`) rather than the display label — so
"I always want Done open" holds across projects and across reloads. Body element ids stay
per-project, so two project pages never collide.

**This reads no completion-model field.** Grouping keys off the rendered display chip, not
`ph.bucket`, not `ph.weight`, and not `isActivePhase` — `overallPct`, `activePhases` and every
metric are untouched by it.

Measured on BIMpossible Platform at 1425 px: all **18** phases present and accounted for, grouped
**12 / 4 / 2**; default page height **5,173 px** against **6,008 px** with all groups expanded —
**835 px** saved without removing a single row.

### 6.11 Contrast and target size — rerun 2026-08-31

The figures in §6.8 were wrong and are replaced by these. The earlier contrast scanner enumerated
fewer views than it reported, and the earlier target sweep never reached project-page audit history.
Both were rerun with every disclosure force-expanded, so folded content is measured too.

**Method.** A `TreeWalker` over every rendered text node. An element's painted ground is composited
root-first — parent ground first, then the element's own surface on top — because doing it the other
way round produces phantom failures on translucent chips. Threshold 4.5:1, relaxed to 3:1 only for
text ≥ 24 px or bold ≥ 18.66 px. Target sweep measures every `button`, `a`, `[onclick]`, `input` and
`select` with a non-zero box.

| Sweep | Result |
|---|---|
| Contrast, 21 views, default state, 1425 px | **0** failures across **2,855** composited text nodes |
| Contrast, 21 views, every disclosure force-expanded, 1425 px | **0** failures across **4,048** composited text nodes |
| Controls under 24 px, force-expanded, 1425 px | **0** across all 21 views |
| Horizontal overflow, force-expanded, 1425 px | **0** across all 21 views |
| Overflow + target size at **753 px**, force-expanded | **0** / **0** — Overview, BIMpossible, Add-Ins, Toolkit, BIM Watch |
| Overflow + target size at **375 px**, force-expanded | **0** / **0** — Overview, BIMpossible, BIM Watch |

The narrow-width rerun is a targeted subset, not all 21 views: it covers the surfaces this pass
actually changed (project hero and phase groups, audit-history links, the BIM Watch panel) plus the
two densest list views. The full 21-view sweep was run at 1425 px only.

| Defect | Measured | Fix |
|---|---|---|
| `.ah-ref.au-jump` audit-report links, project pages | 18 px tall target | `min-height:24px` + inline-flex, type unchanged ([index.html:400](../index.html:400)) |
| `.ov-group.pers` Personal group label | **3.27:1** at 10 px | `rgba(251,146,60,.55)` → `.78` ([index.html:797](../index.html:797)) |
| BIM Watch stale-source `check` link | **1.60:1** — no CSS rule at all, so it fell back to the UA's `#0000ee` | `.bw-warn a{color:var(--w)}`, plus a 24 px box ([bimwatch-panel.js:34](../bimwatch-panel.js:34)) |

standalone actions; 24 px AA minimum (WCAG 2.5.8) for dense inline chips. Dense controls are not
re-inflated to 44 px — that would undo the density the check-in surfaces depend on.
