# Mission Control — UX Audit & Rework Spec
**Date:** 2026-08-30 · **Scope:** `Dashboard/index.html` (3,109 lines) + the data it renders
**Method:** live instrumentation of the running app (measured DOM, computed contrast, per-view metrics) + `ui-ux-pro-max` rule base
**Verdict:** the app is not a dashboard. It is an **archive rendered with dashboard chrome.**
**Status:** rework shipped 2026-08-30, second pass 2026-08-31 — measured results in
[§6 As built](#6-as-built), latest changes in [§6.6](#66-second-pass--2026-08-31).
Sections 1–5 are the original findings and spec, left unedited so the before/after is legible.

---

## 1. The one-sentence diagnosis

The dataset is a *ledger* — phase notes are changelog paragraphs written for archaeology.
The UI treats every ledger field as **display copy** and prints it raw. So the landing page
answers *"tell me everything ever known about this portfolio"* when a daily check-in needs
*"what changed, what's on fire, what's waiting on me."*

Both questions are answerable from the data that already exists. Only the first one is being asked.

### 2.2 Root cause of the page weight

```js
`<span class="nm">${esc(ph.name)}${ph.note?` <span class="nt">– ${esc(ph.note)}</span>`:''}</span>`
```

The dataset holds **55,188 characters of phase notes** across 63 phases. The ten largest:

An 8,064-character paragraph is a **~1,300-word essay printed inside a progress-bar label**.
This single line is responsible for roughly 70% of both oversized views.

## 3. What a daily check-in actually needs

The check-in loop, in order:

1. **Did anything break?** → blockers, urgent audit findings, stale data
2. **What moved since I last looked?** → dated activity feed, marked *new since your last visit*
3. **What's waiting on me?** → owner-gated decisions, reminders
4. **What do I do next?** → ranked next-actions

Everything else — phase archaeology, codebase graph, toolkit, per-phase task lists — is **reference**.
Reference must remain reachable. It must not be the landing page.

## 4. The rework

### 4.1 New default view: **Today**

Four bands, one screen:

- **Attention** — blockers, urgent audit findings, stale-data warning. Each row is actionable and links straight to its project.
- **Since your last check-in** — the 56 dated `recent` entries merged across all 12 projects into one reverse-chronological feed, grouped by day, with entries newer than the last visit (`localStorage: dash.lastVisit`) flagged. Falls back to "last 7 days" on first run.
- **On your desk** — `pendingDecisions` + `blockers` + `reminders`, grouped by project, deduplicated. This is the owner-gated queue.
- **Movement** — projects that actually moved in 14 days, with sparkline + last-commit line. Dormant projects collapse into a single "Quiet" row.

### 4.2 Kill the prose wall

- Phase notes clamp to **2 lines**, expand on click (full note preserved, nothing lost).
- Derive a **status chip** from the note's leading token (`ACTIVE` / `CLOSED` / `PARTIAL` / `LIVE` / `ON HOLD` / `CONDITIONAL` / `PROPOSAL` / `PLACEHOLDER`) — parses cleanly for the phases that use the convention, falls back to no chip.
- Projected effect: Overview **9,003 → ~1,900 px**; BIMpossible **16,176 → ~3,400 px**.

### 4.3 Navigation

- Group into **Today / Work / Reference / Personal**; dormant projects collapse under a disclosure.
- Nav rows become real `<button>`s inside a `<nav>` landmark: focusable, `aria-current`, 44 px min height.
- **Command palette** (`Ctrl/Cmd-K`) searching projects, views, phases, and activity entries.
- `g` then a key for direct jumps; `?` for the shortcut sheet.

### 4.4 Accessibility pass

- `--dim` → `#707d97` (4.83:1), `--status-dim` → `#7884a0` (5.34:1).
- All interactive elements ≥ 44 px, visible focus ring.
- Skip link, `<nav>` landmark, `aria-current="page"`, real `<h3>` section headings.
- Replace emoji icons with the existing inline-SVG `ICO` set.

Heights are content-dependent — the ledger changes daily, so these are the 2026-08-31 measurement

Strategy and Toolkit first *grew* (+11% / +13%) under the target-size pass: both are almost

controls too small to hit — and then paid off properly with section disclosures (§6.6), which is
where the −60% / −64% comes from.

A second-order find during the rework: the project page's inline **Audit card measured 4,261 px —
larger than the entire dedicated Audit view (1,210 px)** — because it rendered every open finding
and every history run inline. `revealBlock()` folds the tail away without removing anything from
the DOM.

**On the 44 px target:** the original spec called for 44×44 everywhere. As built, the 44 px
comfortable target (WCAG 2.5.5) applies to primary navigation and standalone actions; the dense
inline controls inside a card — pills, chips, "show more" toggles — hold the **24 px AA minimum
(WCAG 2.5.8)**, which is the exception that criterion is written for. Forcing 44 px on all 958
controls would have re-inflated every view the clamp work just shrank. 475 of 958 controls sit
between 24 and 44 px; none sit below 24.

### 6.4 Root causes worth remembering

- **Contrast must be measured on the composited surface.** Reading
  `getComputedStyle().backgroundColor` returns the *specified* rgba, not the painted colour, and
  produced 974 false failures. The binding surface here is the lightest raised card,
  `rgb(27,34,56)` — not `--bg #07080d`, which flatters every value by roughly 1.2.
- **A bare `fr` grid track is `minmax(auto, 1fr)`,** and the auto minimum is the item's
  min-content. One phase card with a 557 px min-content stretched its track past a 360 px
  viewport. Every text-bearing track is now `minmax(0, 1fr)`.
- **Inline styles beat responsive CSS.** The DAG chips carried `white-space:nowrap` inline, so no
  media query could let them wrap. Their presentation now lives in a class.
- **`overflow-wrap` is inherited,** so one `break-word` on `#main` covers every ledger string in
  every view; the flex and grid items that also need a smaller min-content get `anywhere`
  explicitly.
- **The UA sheet's `[hidden]{display:none}` is a bare attribute selector,** so any class that sets
  its own display outranks it. `.tk-grid{display:grid}` meant seven "collapsed" Toolkit sections
  kept their full height while correctly reporting `hidden === true`. A global
  `[hidden]{display:none!important}` now has the last word, since every disclosure here relies on
  the property.
- **Never override `display` in a blanket sizing rule.** `#main button{display:inline-flex}` — added
  to make min-height bind on inline chips — silently clobbered `.tv-row`'s `display:grid` and
  staggered the Movement band. Sizing rules set sizes; only the named inline chips get a display.

### 6.5 Left standing

- **BIM Watch** still renders ~3 words in a 900 px view. It is a data problem, not a UI one — the
  view is wired and will fill when the feed does.
- **Emoji in `data.js`** are ledger content regenerated by the sync scripts; fixing them belongs
  upstream, not here.

### 6.6 Second pass — 2026-08-31

- **Toolkit sections fold.** Each of the seven section headers is now a full-width
  `<button aria-expanded aria-controls>` with a caret and a count; only the first opens by default.
  Search and category filters force-open any section holding a match, and clearing the filter
  restores whatever you last set (`dataset.userSet`) or the default. 9,477 → 2,178 px.
- **Strategy sections fold** on the same pattern. Because every filter and sort re-renders the view
  wholesale (`show('strategy')`), the fold state can't live on the element — it persists in
  `localStorage` under `strat.secOpen`, keyed by category. Filtering to one category always leaves
  it open. 4,607 → 1,836 px.
- **AI-Server and AI Brain Data moved to Personal.** The Overview satellite grid is now derived from
  the `WORK` array rather than a second hardcoded list, so the sidebar and that grid can no longer
  drift apart.
- **Today's "nothing new" heading** used to read *"nothing new since your last visit"* directly above
  eight listed entries. It now says *"Nothing new since {date} · last N updates for context"*.
- **The Overview activity footer wraps.** The 14-day heat strip is fixed-width and can't shrink, so
  at 375 px it pushed the timestamp 13 px past the viewport — the last remaining horizontal scroll.
- Re-verified after all of the above: 21 views render with 0 runtime errors, 0 horizontal scroll at
  375 / 768 / 1425 px with every disclosure expanded, 0 contrast failures across 3,464 text nodes,
  0 targets under 24 px.
